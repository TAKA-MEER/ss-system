# 使い方（実機）

**実装を知らない試験担当者が、実機で本システムを動かすための手順書。**「今回何を確かめるか」は [試験項目.md](試験項目.md)。
ここに書いた操作・文言・既定値を変えたら、同じコミットでこの文書も直す（`CLAUDE.md`）。

本システムは、ノートパソコンの Docker の中で動く。ホストの端末からは **`scripts/ss.sh`** だけを打つ（リポジトリ直下で打つ。どこから打っても動く）。

| やること | コマンド | 節 |
| --- | --- | --- |
| カメラの角度のずれを測る | `scripts/ss.sh calib …` | §3 |
| 本システムを起こす | `scripts/ss.sh start` | §4 |
| 状態を見る | `scripts/ss.sh status` | §4 |
| 盤の位置を依頼する | `scripts/ss.sh locate` | §5 |
| 記録を見る | `scripts/ss.sh logs [-f]` | §7 |
| 止める | `scripts/ss.sh stop` | §6 |

---

## 1. 準備（初回だけ）

| もの | 確かめ方 |
| --- | --- |
| Docker | `docker ps` が動く（`sudo` なしで） |
| イメージ `ss-system:dev` | 無ければ `start` が作る（数分かかる）。手で作るなら `docker build -t ss-system:dev -f docker/Dockerfile .` |
| 学習済みモデル | `model/lug_v3_s.pt` を置く（git には入っていない）。無いと `start` が止まる |
| 機器とのつながり | ノートパソコンが、カメラモジュール（UnitV2。今は `192.168.5.129`）と昇降部に届くネットワークにいる。`ping 192.168.5.129` |

**2026-11-19 時点で、昇降部はまだ実機に入っていない**（hve-system 待ち）。それまでは、本物の機器で依頼（§5）はできない。できるのは次の 2 つ:

- カメラの角度のずれを測る（§3。カメラモジュールだけを使う）
- 偽の機器で手順をひととおり試す（`scripts/ss.sh start --fakes`。機器は何も動かない）

## 2. 使う前に毎回やること

1. **カメラのヨーの 0° を合わせる。**人が機体の正面にカメラを向け、カメラモジュールの画面（またはボタン）で 0° を押し直す。合わせないと、依頼は `camera_pose_unknown` で返る。
2. **カメラの角度のずれを測る（§3）。**次のどれかがあったら、必ず測り直す:
   - カメラに触れた（ピッチの基準が数 °変わることがある）
   - ヨーの 0° を合わせ直した
   - カメラモジュールを再起動した
3. 測った値を `ss_ws/src/ss_locator/config/locator.yaml` に書き、本システムを起こし直す（§3 の 4）。

## 3. カメラの角度のずれを測る（`calib`）

本システムが動いていると撮れない（どちらもカメラを動かすため）。先に `scripts/ss.sh stop`。

1. 模擬天板に吊り金具を 2 個以上置き、巻き尺で測る:
   - 金具の水平の位置（m）。機体の原点から、**前が x、左が y**
   - 天板の床からの高さ（m）
   - 昇降部の昇降量（m。hve の画面で読む。0 なら 0）
2. 金具が写る向きを、ヨー・ピッチの度で 3〜8 個決める（例: `12:25,23:25,34:25`。左が正のヨー、ピッチは見下ろす角）。
3. 撮って当てはめる:

   ```bash
   scripts/ss.sh calib --lugs "2.07,0.26;2.27,-0.26" --top-height-m 0.78 --lift-height-m 0 \
     --poses "12:25,23:25,34:25"
   ```

   カメラが順に向きを変えて撮り、最後に元の向きへ戻る。写真と観測は `out/calib-<時刻>/` に残る。
   終わると、`locator.yaml` にそのまま書ける 3 行（`camera_pitch_offset_deg: …` など）と、測った位置との差（1 枚ごとと全体の `mean`・`max`、m）が出る。
   - 測った位置から 0.3 m より遠い検出は外す（誤検出）。外したものは `rejected:` の行に出る。
   - 差（`mean`）が数 cm に収まらないときは、金具の位置・天板の高さの測り直しを疑う。
4. 出た 3 行（`camera_pitch_offset_deg`・`camera_yaw_offset_deg`・`camera_roll_deg`）を `locator.yaml` の同じ名前の行に書き写す。**道具は設定を書き換えない。**本システムは起動のときだけ設定を読むので、動いていたら `stop` → `start`。

撮り直さずに、保存した観測から当てはめ直すだけなら（本システムが動いていてもよい）:

```bash
scripts/ss.sh calib --from out/calib-<時刻>
```

## 4. 起こす（`start`）・状態を見る（`status`）

```bash
scripts/ss.sh start                      # 本物の機器につなぐ
scripts/ss.sh start --camera-host 192.168.5.129   # カメラモジュールの IP を指定する
scripts/ss.sh start --lift-host <IP>     # 昇降部の名前が引けないとき
scripts/ss.sh start --fakes              # 偽の機器（何も動かない。手順の確認用）
```

- ビルドを含むので、状態の 1 行が出るまで 1〜3 分かかる。`状態: interface_version=3  phase=IDLE …` が出たら起きている。
- 起きないとき（モデルが無い・コンテナが落ちた・3 分たっても状態が読めない）は、理由とコンテナの記録の最後の 50 行が出て 1 で終わる。
- カメラモジュールの IP は、指定しなければ昇降部から教わる。
- 本システムは 1 つだけ動かす。動いているのに `start` すると何もせず 1 で終わる。

`scripts/ss.sh status` で状態を 1 行出す（`phase` が `IDLE` なら依頼を受けられる）。

## 5. 盤の位置を依頼する（`locate`）

```bash
scripts/ss.sh locate                          # 全周・最大 5 m・制限時間 120 s
scripts/ss.sh locate --from-deg -45 --span-deg 90   # 前の ±45° だけ
```

1. 依頼の中身と「昇降機とカメラが動きます。よろしいですか？ [y/N]」が出る。**周りに人がいないことを確かめて `y`。**`--yes` で聞かずに出す。
2. 段（上昇・走査・後片付け）が変わるたびに 1 行出る。**Ctrl+C で取り消す**（昇降機を戻すまで待つ）。もう 1 回 Ctrl+C で待たずに終わる（昇降機が戻ったか見ていない）。
3. 結果の表が出る。**「後片付けの完了まで、機体と昇降機を動かさないでください」が出たら、完了の行が出るまで触らない。**
4. 図（上から見た図。機体の前が上）と記録が `out/<時刻>.png`・`out/<時刻>.json` にできる。`--plot`・`--json` で場所を変えられる。

| 引数 | 既定 | 意味 |
| --- | --- | --- |
| `--from-deg` | −180 | 方向の範囲の開始（°。機体の前が 0・左が正） |
| `--span-deg` | 360 | 範囲の幅（°。開始から左回り） |
| `--max-distance-m` | 0 | 探す最大の距離（0 は既定の 5 m） |
| `--time-limit-s` | 120 | 制限時間 |
| `--yes` | — | 確認を省く |

**表の読み方**: 長さは m・角度は °。x は前、y は左。奥行の `*` は測っていない（既定値）。向きσ の `不明` は対角の金具 2 個だけの盤。正面の `-` は正面の向きが分からない。

**盤が 0 面のとき**は理由が 1 行出る:

| 理由 | 意味 | まず確かめること |
| --- | --- | --- |
| `completed` | 最後まで見終えた（盤が無かった） | 範囲・距離 |
| `no_lugs` | 吊り金具が見えない | 範囲・距離・明るさ |
| `lugs_ungrouped` | 金具は見えたが盤に組めない | 金具の付き方 |
| `no_image` | 画像が取れない | カメラモジュールのつながり |
| `lift_refused` | 昇降機が動かない・拒否された | 昇降部の画面 |
| `camera_too_low` | 必要な高さまで上がれない | 天井・上端 |
| `ceiling_unknown` | 天井までの距離が分からない | カメラモジュールが昇降部につながっているか |
| `camera_pose_unknown` | カメラの向きが分からない | ヨーの 0°（§2）・カメラモジュールの再起動 |
| `canceled` | 取り消した | — |
| `timeout` | 時間切れ | `--time-limit-s` |
| `human_override` | 人の操作で中断した（昇降機もカメラも戻さない） | — |

**終了コード**: 0 結果と後片付けの完了を受けた（理由は問わない）・2 引数の誤り・3 本システムが応えない／口の版が合わない・4 別の依頼の最中／拒否・5 後片付けの完了が届かない・130 待たずに終わった・1 本システムが動いていない。

## 6. 止める（`stop`）

```bash
scripts/ss.sh stop
```

- **依頼の最中（`phase` が `IDLE` でない）は止めない**（4 で終わる）。止めると昇降機を元の高さに戻さないため。どうしても止めるときは `--force`（そのあと昇降機は hve の画面で戻す）。
- 止めるとコンテナを消す。設定を変えたら `stop` → `start`。
