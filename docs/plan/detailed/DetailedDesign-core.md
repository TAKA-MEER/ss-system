## 2. カメラの外部パラメータ

試作は外部パラメータ（ワールド → カメラの 4×4 `T`）を既知として受ける。本システムは**昇降機の高さ・ヨー・ピッチから作る**（[Spec.md](../spec/Spec.md) §1.2）。

| 入力 | 出どころ |
| --- | --- |
| 高さ | hve-system の昇降部が配信する値（[Spec.md](../spec/Spec.md) §1.2）。**ピッチの回転軸の床からの高さ** = 配信値 + `camera_height_offset_m`（2026-11-18 に「光学中心」から改めた。光学中心はこれより `b sin θ` 低い。昇降の目標と `min_camera_height_m` の判定はこの高さのままでよい（差は 6 cm 以内）） |
| ヨー | **hve-system の改良待ち**（hve `H-A11`）。それまでは偽のカメラが返す値 |
| ピッチ | **サーボの目標角を信頼する**（[Spec.md](../spec/Spec.md) §1.2）。本システムが送った目標角を使う |
| 取付の位置 | ヨーの回転軸の `base_link` での位置 `camera_mount_x_m`・`camera_mount_y_m`、ヨーの回転軸からピッチの回転軸までの水平・前向きの距離 `camera_forward_offset_m`（a）、ピッチの回転軸から光学中心までの光軸に沿った距離 `camera_optical_offset_m`（b）（[-names.md](DetailedDesign-names.md) §5。a・b・高さは 2026-11-18 実測） |
| 取付の角度のずれ | `camera_yaw_offset_deg`（δψ）・`camera_pitch_offset_deg`（δθ）・`camera_roll_deg`（φ）。**校正の道具（§2.1）で求めて設定に書く**（2026-11-18 ユーザー決定） |

計算（`geometry.camera_T(height_m, yaw_rad, pitch_down_rad, mount)`）:

- 角度: ψ = 応答のヨー + δψ、θ = 応答のピッチ + δθ（ずれは足すだけ。0 なら今までと同じ）
- 向き: 前 `f = (cos ψ cos θ, sin ψ cos θ, −sin θ)`、右 `r₀ = (sin ψ, −cos ψ, 0)`、下 `d₀ = f × r₀`（ψ = ヨー、θ = 見下ろしの角。下向きが正）
- 光軸まわりの傾き: `r = r₀ cos φ + d₀ sin φ`、`d = −r₀ sin φ + d₀ cos φ`（φ が正 = カメラの右が下へ回る向き）
- OpenCV のカメラ（x 右・y 下・z 前）から `base_link` への回転 `R = [r d f]`（列）
- 光学中心 `C = (mount_x + a cos ψ, mount_y + a sin ψ, height) + b f`（a = `camera_forward_offset_m`、b = `camera_optical_offset_m`、height = ピッチの回転軸の高さ）
- `T = [Rᵀ | −Rᵀ C]`

ヨー・ピッチの符号と原点は**本システムの決まり**（ヨーは機体の前が 0・左が正、ピッチは見下ろしが正。[-locate.md](DetailedDesign-locate.md) §1 と同じ）。hve-system の値との変換は `hve_camera.py` の中だけで行う。

内部パラメータ（`K`・歪み `k1`・`k2`）は 1280×720 でチェッカーボードを使って 1 回校正した値をパラメータファイルに持つ（[Spec.md](../spec/Spec.md) §1.2）。**歪みのモデルは試作と同じ k1・k2 だけ**（試作の射影がこの形のため）。


### 2.1 取り付けの角度のずれを求める（校正の道具 `mount_calib`。`WP-CAL-02`）

床からの高さと水平の位置を巻き尺で測った金具（2 個以上）を、ヨー・ピッチを変えて何枚か撮り、δψ・δθ・φ を求める。本番の流れ（ノード）は通さない道具。

1. 撮る: カメラの向きが分からない（原点を合わせていない・再起動のあと）なら動かさずに終わる。指定した向きへ順に向け、着いたら `settle_s` 待って静止画を撮り、検出器で金具の画素を得る。向きは応答のヘッダの値を使う。人の割り込み・失敗が来たらそこで止める（動かさない。それまでの写真で当てはめる）。撮り終えたら撮る前の向きへ戻してから手を離す。写真と、観測（ヘッダの向き・金具の画素）の json を保存し、json だけから当てはめ直せるようにする。
2. 当てはめる（純関数）: 画素を §2 の式（ずれを入れた `camera_T`）で天板の高さの面に下ろし、測った位置との差を最小にする（最小二乗）。どの測った金具に当たるかは、ずれの候補（δψ ±10°・δθ ±6° の格子、0.5° 刻み）ごとに一番近い金具に割り当てて差の合計が最小のものから始め、当てはめたあとにもう一度割り当て直して確かめる。**高さは既定では動かさない**（ピッチのずれと区別がつかない。2026-11-18 の模擬天板で確かめた）。
3. 出す: 3 つの値（度）と、観測ごとの差・平均・最大を出し、`locator.yaml` に写す行を出す。**設定ファイルは書き換えない**（人が見て写す）。

2026-11-18 の模擬天板（金具 2 個・5 枚）では δθ −2.6°・δψ −5.4°・φ +4.1° で差は平均 1.9 cm・最大 4.4 cm（入れないと 0.30 m）。
## 3. 走査の計画

| 項目 | 決まり |
| --- | --- |
| 水平の画角 | 内部パラメータから求める: `hfov = 2 atan(640 / fx)` |
| 刻み | `step = hfov × (1 − scan_overlap_ratio)`（[Spec.md](../spec/Spec.md) §1.2「画角が少し重なる刻み」） |
| 撮るヨー | 幅 `span ≤ hfov` なら範囲の中央で 1 枚。それより広ければ、最初の画像の左端を範囲の開始に、最後の画像の右端を範囲の終わりに合わせ、そのあいだを `step` 以下の等間隔で埋める。**全周（幅 2π）は `ceil(2π / step)` 枚を等間隔** |
| 並び | 範囲の開始から反時計回りの順に撮る |
| 見た方向の範囲 | 撮って検出まで終えた画像ごとに `[ヨー − hfov/2, ヨー + hfov/2]` を取り、依頼の範囲で切り、重なりをまとめる |
| ヨーが届かない方向 | **未定**（hve のヨーの届く範囲が分からない。[-open.md](DetailedDesign-open.md) §1） |

ピッチは `scan_pitch_down_deg` に固定する（[Spec.md](../spec/Spec.md) §1.2「ピッチを固定し」）。値は暫定（[-names.md](DetailedDesign-names.md) §5）。

## 4. 組み立ての結果から返す盤へ

試作の `fit` の出力（中心・正面の向き・幅・奥行・金具の数・正面が分かるか・対角か）を、[-locate.md](DetailedDesign-locate.md) §2.3 の `PanelTop` に直す。

| `PanelTop` | 求め方 |
| --- | --- |
| `x_m`・`y_m` | `fit` の中心 |
| `yaw_rad` | 矩形の 4 辺の外向きの法線のうち、**中心から機体の原点へ向かう向きに最も近いもの**（基準の辺の法線） |
| `width_m`・`depth_m` | 基準の辺の長さ・それと直交する辺の長さ。試作の幅・奥行（金具の位置から角までの `LUG_INSET` を足したもの）を、基準の辺に合わせて入れ替える |
| `top_height_m`・`height_measured` | `top_height_default_m`・false |
| `lugs` | 組に使った金具の数 |
| `front_known`・`front_yaw_rad` | 金具 2 個（背中合わせ）で正面が決まったとき true と、`fit` の正面の向き |
| `pos_std_m` | `sqrt( Σ s_posᵢ² / n² + e² + a² )`。`s_posᵢ` は金具ごとの位置のばらつき（試作の `lift`・`fuse`）、`e` は中心からリング面の線までの距離の平均（組分けの残差）。**`a` は金具 2 個で正面が分かる盤だけ `r̄ × radians(s̄_axis)`**（`r̄` は金具から中心までの距離の平均、`s̄_axis` は金具のリング面の向きのばらつき [°] の平均。中心をリング面の向きから決める分のばらつき）。それ以外の盤は `a = 0`（2026-11-06。[source/std-check.md](../source/std-check.md)） |
| `yaw_std_deg` | `degrees( atan( √2 × mean(s_posᵢ) / width_m ) )` |

確からしさの式は、合成データで推定の誤差と比べて確かめた（`WP-EST-02`・`WP-EST-03`）。**`a` を足す前は、金具 2 個の盤の位置の標準偏差が小さすぎた**（1σ 以内 31%）。足したあとは 1σ 以内 70%・2σ 以内 88%。金具 3〜4 個は大きめ（1σ 以内 97%）で、安全側なので直さない（2026-11-06 実装管理担当が決めた。ユーザーが任せた）。

**返す盤の絞り込み**: 中心の方位角が依頼の範囲に入り、`base_link` の原点からの水平距離が `max_distance_m` 以下の盤だけを返す。
**金具が対角の 2 個だけの盤**（試作の `fit` が `diagonal` を付けたもの）も返す（[Spec.md](../spec/Spec.md) §1.1。2026-11-05 ユーザー決定）。中心は 2 個の中点、幅・奥行は試作どおり 2 個の距離 ÷ √2、`yaw_rad` は上の規則で選んだ辺、**`yaw_std_deg` は 90**、`front_known` は false。

### 4.1 四隅が写らない盤と、背中合わせの盤（2026-11-18。[Spec.md](../spec/Spec.md) §1.1「背中合わせの盤」「奥行き」・§1.2「吊り金具の数」「金具の取り付け角」）

前提: 吊り金具は盤 1 面ごとに四隅に必ずある。背中合わせの 2 面は 1 つの盤として返す。写った金具が 2 個でも盤にする。

**試作の組み立て（`assemble.assemble`）はそのまま回す**（`assemble.py` は変えない。試作との一致の試験を残す）。そのあとで次の 1〜4 を行う。

| # | やること |
| --- | --- |
| 1 | **面のかけら（以下「かけら」）を作る。**`assemble` の盤のうち金具 3〜4 個の盤は、そのまま 1 つのかけら（矩形。両端の金具の列を測った）。金具 2 個の盤（対角を含む）は捨て、その金具を 2 の候補に戻す |
| 2 | **金具 2 個の組を作る。**3〜4 個の盤に入っていない金具から、条件 (a)〜(d) をすべて満たす 2 個を組の候補にする。(a) 間隔 `d`（金具の中心どうし）が `two_lug_spacing_min_m`〜`two_lug_spacing_max_m`。(b) 2 個を結ぶ線分の途中にほかの金具が無い（`assemble._between`）。(c) `assemble._pair_center` の点 `c` が求まる。(d) **継ぎ目をまたぐ斜めの組でない**（下の「継ぎ目のわな」） |
| 3 | 候補を、確信度（`conf`）の和の大きい順に取る。取った組の金具を含む候補は捨てる。**取った組が 1 つのかけら**になる。広がる側 `n` は、2 個を結ぶ線の法線のうち `(c − mid) · n > 0` の向き（`mid` は 2 個の中点。輪の向きは側を決めるだけに使う）。金具の列はこの線の 1 本だけを測った |
| 4 | **かけらをまとめる。**かけら P と Q が下の「まとめる条件」をすべて満たせば、1 つの盤にする（背中合わせの 2 面のほか、輪の向きがずれて試作の組み立てが 2 組に割れた 1 面もここでまとまる）。1 つのかけらがまとまる相手は高々 1 つ（`conf` の和の大きい組み合わせから取る）。まとまらなかったかけらは、1 面の盤として返す |

**かけらの形**: 向きの軸 `u`（金具の列に沿う）と法線 `n`、`n` に沿った**金具の列の位置** `s_near`・`s_far`（機体の原点に近い方・遠い方）、`u` に沿った金具の範囲、それぞれの列を**測ったか**（`measured_near`・`measured_far`）。3〜4 個の盤は両方の列を測った。金具 2 個の組は、測った列が 1 本で、反対側の列は `two_lug_depth_default_m − 2 × LUG_INSET` だけ広がる側へ離れた所に置き、測っていない印を付ける。

**まとめる条件**: (i) 向きの軸の差が `back_to_back_angle_tol_deg` 以内（180° 周期）。(ii) `n` に沿って重ならない。(iii) **向かい合う 2 本の列（P の Q に近い方の列と、Q の P に近い方の列）が、どちらも測った列**。(iv) `u` に沿った金具の範囲の重なりが、短い方の `back_to_back_overlap_ratio` 以上。(v) 向かい合う 2 本の列の間の距離 `D` が、下の表の範囲に入る。

`k` は、向かい合う列から見て**相手の側へ広がっている**かけらの数（3〜4 個のかけらは常に相手と反対側へ広がる。金具 2 個の組は広がる側 `n` で決まる）。`L = LUG_INSET`、`g₀`・`g₁` は `back_to_back_gap_min_m`・`back_to_back_gap_max_m`、`d₀`・`d₁` は `panel_depth_min_m`・`panel_depth_max_m`、`t` は `merge_tol_m`。

| `k` | 何とみなすか | `D` の範囲 |
| --- | --- | --- |
| 0 | 継ぎ目をはさむ 2 面 | `g₀`〜`g₁` |
| 1 | 2 面のうち片方は丸ごと、もう片方は外側の列だけ | `d₀ − 2L + g₀`〜`d₁ − 2L + g₁` |
| 2 | 1 面の手前と奥の列 ／ 2 面の外側の列どうし | `d₀ − 2L − t`〜`d₁ − 2L + t` ／ `2d₀ − 2L + g₀`〜`2d₁ − 2L + g₁` |

**継ぎ目のわな**: 継ぎ目をはさむ 2 列は約 0.135 m（`2 × LUG_INSET`）しか離れていないので、列をまたぐ斜めの 2 個（約 `√(0.53² + 0.135²)` ≈ 0.55 m）も間隔の条件を通る。金具 `i` と `k` の距離が `back_to_back_gap_min_m`〜`back_to_back_gap_max_m` なら「継ぎ目の隣」と呼び、候補 `(i, j)` を次のとき捨てる。① `i` の継ぎ目の隣 `k` と `j` の継ぎ目の隣 `l` があり、**`k` と `l` が線 `i–j` から `back_to_back_gap_min_m / 2` 以上離れて反対側にあり、`| |k − l| − |i − j| |` が `back_to_back_gap_min_m` 未満で**（継ぎ目の 2 本の対角線はほぼ同じ長さ。横に並んだ盤の隣の金具どうしは `2 × 継ぎ目` ほど長い）、線分 `i–j` と `k–l` が交わる（4 個とも写ったときの斜め）。**離れていることを確かめないと、横に並んだ盤の同じ列の金具（ほぼ一直線）が誤差で「交わる」になり、正しい組を捨てる**（2026-11-18 に実装管理担当の試しで、1 cm の誤差で 200 回中 75 回）。② `i` の継ぎ目の隣 `k` があり、`|k − j| < |i − j|`（3 個だけ写ったとき。直角の辺は斜めより短い。差は約 0.017 m しかないので、**誤差で取り違えうる**。分かっていること）。

**返す盤**（まとめた盤も 1 面の盤も同じ）:

| `PanelTop` | 求め方 |
| --- | --- |
| 列の範囲 | `n` に沿って、まとめたかけらの列の最も近い位置から最も遠い位置まで。`u` に沿って、金具の範囲の和 |
| `x_m`・`y_m` | 列の範囲を `LUG_INSET` ずつ外へ広げた矩形の中心 |
| `yaw_rad`・`width_m`・`depth_m` | その矩形に §4 の表の規則（基準の辺は機体側に最も向いている辺）を当てる |
| 奥行きを測ったか | 一番手前と一番奥の列を、どちらも測ったとき true（版 3 の `depth_measured`。[-locate.md](DetailedDesign-locate.md) §2.3。今は口に出さない） |
| `lugs` | 使った金具の数の和 |
| `front_known`・`front_yaw_rad` | false・0 |
| `pos_std_m` | 3〜4 個のかけらは §4 の式、金具 2 個の組は `sqrt( (s_pos₁² + s_pos₂²) / 4 )`。まとめた盤はかけらの値の二乗平均の平方根。**そこへ、測っていない一番外側の列 1 本につき `two_lug_depth_std_m²` を足す** |
| `yaw_std_deg` | §4 の表と同じ式（使った金具の `s_pos` の平均と、幅） |

**分かっていること**: 背中合わせなのに外側の列が 1 本しか写らず、もう一方の面の金具も写らないと、1 面とみなすので中心が約 0.5 m ずれる（spec のとおり。`pos_std_m` には入らない）。1 面の 4 個が写れば、どの 2 個ずつで組を作っても、まとめた列の範囲は同じ矩形になる。継ぎ目の 2 列だけが写ったときは、2 面と分かるので奥行きは 2 面分になり、測っていない列が 2 本になる。対角の 2 個は間隔が約 0.95 m 以上なので組にならない（`lugs_ungrouped`）。

`reason` の `no_lugs` と `lugs_ungrouped` の区別は、**範囲内で金具が 1 個でも床に戻せたか**で決める（[-locate.md](DetailedDesign-locate.md) §2.4）。

## 5. 依頼の流れ（`locate_core`）

`locate_core` は状態（`IDLE`／`RUNNING`／`CLEANING`）と、`RUNNING` の中の段（`RAISING`／`SCANNING`／`ESTIMATING`）を持つ。
**時刻・出来事（昇降機の状態・画像が届いた・検出が終わった・取り消し・人の割り込み）を受けて、次の命令（昇降機・カメラ・結果を返す・後片付けの完了）を返す。**ROS 2 と hve-system への送受信は `locator_node` が行う。

| 段 | やること | 次へ | 途中で終わる |
| --- | --- | --- | --- |
| 受け付け | 依頼を確かめる（[-locate.md](DetailedDesign-locate.md) §2.1）。**カメラの向きが読めなければ、動かさずに `camera_pose_unknown`**（版 2）。**今の昇降機の高さ・カメラのヨー・ピッチの目標角を「元の高さ・向き」として覚える** | `RAISING` | 拒否（何も動かさない） |
| `RAISING` | 昇降機を `scan_camera_height_m` に合わせる高さ（`scan_camera_height_m − camera_height_offset_m`）へ動かす。**受け付けた時点で昇降部の高さがまだ届いていなければ、動かさずに `lift_refused`**（原点を取る前の hve は目標の高さへの移動を受け付けないのと同じ扱い。元の高さが分からないので `lift_restored: false`） | 着いた → `SCANNING` | 光学中心が `min_camera_height_m` に届かないまま止まった（天井など）→ `camera_too_low`。拒否・動かない → `lift_refused` |
| `SCANNING` | 撮るヨーの順に: ヨーとピッチを向ける → `settle_s` 待つ → 静止画を 1 枚要求 → 検出 → 金具を床に戻す | 全部撮った → `ESTIMATING` | 画像が `image_timeout_s` 来ない → `no_image`。**カメラの向きが読めなくなった（カメラモジュールが再起動した）→ `camera_pose_unknown`。撮り直さない**（再起動するとヨーの向きが読めなくなる。2026-11-16 ユーザー決定。`WP-LOC-03` で直した。**上昇中に読めなくなっても同じ**） |
| `ESTIMATING` | 撮った画像の金具をまとめて組み立て、返す盤に直す（§4） | 結果を返す → `CLEANING` | — |
| `CLEANING` | 昇降機を元の高さへ、カメラのヨー・ピッチを元の向きへ戻す（`human_override` ではどれも戻さない）。カメラと昇降機から手を離す | 後片付けの完了を出す → `IDLE` | 後片付けの上限（[-locate.md](DetailedDesign-locate.md) §3。版 2 では距離 ÷ 速さ ＋ 余裕）を過ぎた → 手を離して `lift_restored: false` |

**どの段にいても**、次のときはその場で止め、それまでの金具で組み立てて結果を返し、`CLEANING` へ行く:

| 出来事 | `reason` |
| --- | --- |
| 取り消された | `canceled` |
| 依頼を受け付けてから `time_limit_s` を過ぎた | `timeout` |
| hve-system が「人に取って代わられた・人の操作」を知らせた | `human_override`（昇降機を戻さない） |

元のヨーは、ヨーの向きが読めるようになるまで偽のカメラが返す値を使う（hve `H-A11`。[-open.md](DetailedDesign-open.md) §1）。

## 6. hve-system とつなぐ部分（待ち）

| もの | 待っていること | それまで |

hve-system の昇降部の止めた理由と本システムの `reason`（`lift_refused`・`camera_too_low`・`human_override`）の対応表は [-hve.md](DetailedDesign-hve.md) §4（2026-11-15 案）。

**`WP-HVE-01` で気をつけること**（`WP-LOC-01` の検証で気づいた）: `locate_core` は昇降部の「目標に着いた」をそのまま信じて次へ進む。目標を変えた直後に、前の目標で着いたままの状態が届くと、後片付けで戻り切る前に手を離す。**本物の口では、着いたかを、送った `goto` の `press` と目標の高さまで照らして確かめる**（[-hve.md](DetailedDesign-hve.md) §3。hve が着いたとみなす幅は hve `H-M6`）。人の割り込みは今は昇降部からだけ受けている。カメラモジュールが知らせる場合の扱いは、カメラモジュールの口と一緒に決める（`WP-HVE-02`）。
