## 1. 何をするものか

1280×720 の画像から**天板の吊り金具（JIS B 1168 アイボルト M20）を 1 個ずつ検出**し、
**金具の位置とリング面の向きから、幾何で盤に組み立てる**。盤の高さ 2350 mm を既知として、金具を天板上面の水平面に投影する。

| 段 | やること | コード |
| --- | --- | --- |
| 1. 検出 | YOLO11s-pose（ultralytics）。1 インスタンス = 金具 1 個、キーポイント 4 点（根元・リング中心・リング面の水平方向の両端） | 学習済み `models/lug_v3_s.pt`（約 19 MB） |
| 2. 持ち上げ | 根元 → 天板上面（z = 2.35 m）の点。両端の 2 点 → リング面の向き（180° 周期）。画素 0.5 px のずれから位置・向きのばらつきを見積もる | `src/assemble_lugs.py` `lift`（`src/common.py` の歪み補正つき光線） |
| 3. 統合 | 複数の視点で同じ金具をまとめる（根元が 6 cm 以内）。同じ画像で 3 cm 以内は重複として捨てる | `fuse` |
| 4. 組分け | **リング面は盤の中心を通る**（実物の取付規則）ので、2 個の組の垂直二等分線とリング面の線から中心の候補を作り、支持の多い順に採る | `group` |
| 5. 当てはめ | 金具 3〜4 個 → 長方形（中心・向き・幅・奥行）。**正面と背面は決めない**。金具 2 個 → 背中合わせの盤の正面 2 個とみなし、中心と**正面まで決める** | `fit`・`orient_rows` |

前提（実物で確かめたもの）: 背中合わせの盤は正面側の 2 個だけ、それ以外は 4 個。リング面は盤中心向き（取付のずれは仮に σ 5°、5% はばらばら）。

## 4. 合成データでの成績（`9265d2d` 時点の写し）

評価用 `robot_v3_test`（100 シーン × 4 か所、名札・丸い計器あり）。正は試作の `docs/experiment_log.md` E17・E19。

| 段 | 指標 | 値 |
| --- | --- | --- |
| 金具の検出（`lug_v3_s`、確信度 0.25） | 検出率 / 適合率 | 99.5% / 98.2% |
| | 根元の誤差 中央値 / 90% | 0.35 / 0.79 px |
| | リング面の向き 中央値（5 m 未満・見下ろし 10〜20° / 5° 未満） | 2.7° / 7.6° |
| 盤（4 か所の統合） | 背中合わせ（金具 2 個）: 組み立てた割合・位置 15 cm 以内・正面の取り違え | 84.1% ・ 97.6% ・ 0% |
| | 金具 4 個: 組み立てた割合・位置 15 cm 以内・軸 5° 以内 | 96.1% ・ 95.5% ・ 78.4%（外れはほぼ幅と奥行の取り違え） |

試作が置いた合格ライン（2026-10-31 ユーザー選択）: 検出 95% 以上・位置 ±15 cm・向き ±5°・取り違え 2% 未満。
本システムの目標にするかは決まっていない（[Spec.md](../spec/Spec.md) §3 は「厳密にはしない」）。

## 6. 本システムの仕様との突き合わせ

仕様書を書くときの入力。**どう扱うかは決めていない**（決めるのはユーザー・fk-system）。

| 項目 | 本システムの仕様（[Spec.md](../spec/Spec.md) §1.1・§1.2） | 試作 | 差・確かめること |
| --- | --- | --- | --- |
| 座標 | **ローカル座標系**（依頼を受けた時点の機体が基準）。自己位置・LiDAR の地図は使わない | カメラの外部パラメータを既知とした**ワールド座標**（自己位置 = カメラの位置） | 計算は同じ形で、**機体に対するカメラの位置・向き**（昇降機の高さ・ヨー・ピッチ）に置き換わる。視点を変えて統合するには視点ごとのカメラ姿勢が要る（`SS-A2`） |
| 返す中身 | 盤ごとに**天面の矩形（中心・高さ・向き・幅・奥行き）と確からしさ** | 中心（床上）・向き・幅・奥行・金具の数 | **高さは 2350 mm を前提にした定数**で、測ってはいない。**確からしさは出していない**（金具ごとのばらつきの見積もりはある） |
| 向き（表と裏） | 吊り金具からは区別しない。正面は依頼した側が決める | 金具 4 個は決めない（一致）。**金具 2 個は正面まで決める** | 背中合わせの盤の正面を返すかは仕様に無い |
| 幅と奥行 | 矩形の幅・奥行き | 盤が 1 面だけ・金具 2 個だけ見えるとき、**幅と奥行を取り違える**（90°）ことがある | 矩形としては同じ形なので、仕様上の扱い（どちらを幅とするか）を決める必要があるか |
| 見つからないとき | 空の一覧と理由 | 組み立てられない盤は出さないだけ（理由は返さない） | 理由の種類（金具が見えない・組めない等）は試作に無い |
| 動かす PC | **ノート PC・Ubuntu 22.04・GPU なし**。実機でも Windows でも Docker（Ubuntu 22.04）で動かす。描画と学習は WSL の外、動作確認は WSL の Docker（2026-11-05） | Windows に直接作った Python 環境（`.venv`）・CUDA の GPU で推論。WSL・Docker では動かしていない | **CPU での処理時間は測っていない**（`SS-V3`）。入力 1280 px の YOLO11s |
| 画像 | 必要なときだけ 1280×720 の静止画 | 1280×720（UnitV2 に合わせた） | 一致。静止画は最大約 0.1 秒前のコマ（E13）で、止まって撮るなら問題にならない |
| カメラの向き・高さ | 最適な画角は未定（`SS-V2`） | **リング面の向きは見下ろし角しだい**。見下ろし 10° には、カメラを天板の 0.55 m（盤まで 3 m）〜 0.9 m（5 m）上に置く。5 m より遠い金具は精度が落ちる | 昇降機で上げる高さとピッチを決める材料（`SS-V2`・`SS-A2`） |
| カメラの校正 | 内部パラメータの出どころは未定（`SS-A2`） | 校正していない（チェッカーボードの PDF だけある） | 実物で位置の精度を出すには要る |
| ライブラリ | — | ultralytics（**AGPL-3.0**） | 取り込むなら、ライセンスの扱いを確かめる |

## 7. 試作側で残っている課題（試作の `experiment_log.md`「残っている課題」より）

- 金具 4 個の盤の正面・背面（金具だけでは決まらない）と、盤 1 面だけのときの幅の方向
- 背中合わせの盤の組み立ての取りこぼし（4 か所の統合で 16%）と奥行の誤差（中央値 9 cm）
- 正解つきの実画像がなく、実物での定量評価ができていない
- 手前の金具と重なった金具の見落とし、同じ金具への重複
- カメラの校正、取付高さとピッチ、リングの取付のずれ（仮に σ 5°）と天板の高さのばらつきの実物確認
- 据付後に金具が外されている盤の扱い
