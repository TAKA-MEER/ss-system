## 1. 対象

**配電盤上部を確認するロボットの画像認識を担うシステム**（2026-10-31 ユーザー決定。fk-system [Spec.md](../../../../fk-system/docs/plan/spec/Spec.md) `FD-9`）。
**fk-system（測定機能）から欲しい情報を受け取り、その情報を得るために hve-system のカメラを動かし、画像から推定した結果を返す**（2026-10-31 ユーザー決定。`SSD-3`）。
**配電盤の位置を返すだけの機能として、ほかのシステムから要求される**（2026-11-01 ユーザー決定。`SSD-6`）。
**仕様は fk-system の設計が決める。ただし fk-system 専用にせず、汎用的になるよう意識する。将来作るかもしれない、th-system の前日準備（th-system [Spec-onsite.md](../../../../th-system/docs/plan/spec/Spec-onsite.md) §2）を自動化するシステムにも対応できるようにする**（2026-10-31 ユーザー決定。`SSD-4`）。

| 担当 | 範囲 | 出典 |
| --- | --- | --- |
| **本システム** | **画像認識。**fk-system から欲しい情報を受け取り、**その情報を得るために hve-system のカメラを動かして**推定し、結果を返す | 2026-10-31 ユーザー決定 |
| fk-system | 測定機能。本システムに欲しい情報を渡し、返った結果を使って判断する（人の代わりに操作の判断の一部を行う）。**本システムの仕様を決める** | fk-system [Spec.md](../../../../fk-system/docs/plan/spec/Spec.md) §1・`FD-8`・`FD-9`・`FD-10` |
| th-system | 配電盤上部を確認するロボットのうち、移動に関わるすべて | th-system [Spec.md](../../../../th-system/docs/plan/spec/Spec.md) §1 |
| hve-system | th-system の走行部に載る昇降機と上部カメラ。**カメラと昇降機を本システムが動かす**（昇降機は fk-system も動かす。`SSD-5`） | hve-system [Spec.md](../../../../hve-system/docs/plan/spec/Spec.md) §1 ／ 動かすのは 2026-10-31 ユーザー決定 |

走行の指示は fk-system が出し、走行とカメラ・昇降を組み合わせる判断も fk-system が持つ（fk-system [Spec.md](../../../../fk-system/docs/plan/spec/Spec.md) §1・`FD-2`）。

**昇降機の操作**（2026-10-31 ユーザー決定。`SSD-5`）: **本システムはカメラの位置合わせに昇降機を動かす。fk-system も測定機構を動かすのに昇降機を使う。**
**本システムが昇降機を動かしている間に fk-system が動かさないよう気をつけるのは、指示を出す fk-system。本システムに気にする義務はない。**

### 1.1 求められている情報

**受け取るもの・返すもの**（2026-11-01 ユーザー決定）:

| 項目 | 決まっていること |
| --- | --- |
| 受け取るもの | **盤の位置を探す方向の範囲**（要求する側が指示する） |
| 返すもの | **その範囲にある配電盤の位置** |
| 座標 | **ローカル座標系。LiDAR の地図は考慮しない** |
| 測る点 | 返さない。fk-system が盤の位置から決める |

位置に向き・寸法を含むか、見つからないときに何を返すかは未定（[Spec-open.md](Spec-open.md) `SS-A1`）。

fk-system の測定の流れ（fk-system [Spec.md](../../../../fk-system/docs/plan/spec/Spec.md) §1.1）での使われ方:

| 場面 | 得るために本システムが行うカメラの操作 |
| --- | --- |
| **自律測定の起動直後の配置図**（fk-system §1.1.2）。**起動のたびに作り直す**（前日の地図に関係なく。fk-system `FD-13`） | カメラを上げて周囲を撮る |
| **立会試験中の測定・自律測定の盤前**（fk-system §1.1.1） | **カメラに天面が映るまで走査し、見つけたら推定に最適な画角に合わせる**（最適な画角は `SS-V2`） |

カメラを上げる・走査するのに、**昇降機も本システムが動かす**（`SSD-5`）。**終わったら後片付けとして、昇降機を元の高さに戻す**（2026-11-01 ユーザー決定）。fk-system はこれを当てにせず、走行の前に自分で確かめて下げる（fk-system `FD-14`）。
**画像は、必要なときだけフルサイズの静止画を要求する**（2026-11-01 ユーザー決定。`SS-A6` を決めた）。**フルサイズは 1280×720（720p）**。倍率に関係なく全体が写る 1 枚（hve-system の実機のカメラで 1920×1080 が取れなかったため。hve-system [Spec-ui.md](../../../../hve-system/docs/plan/spec/Spec-ui.md) §1.5・`H-V10`）。**推定の精度とカメラの内部パラメータは、この解像度を前提にする**（2026-11-01 hve-system の実装管理担当からの伝言）。
**移動中はカメラが揺れるので、画像認識はできない前提**（fk-system 決定）。配置図の精度を上げるために、fk-system は定期的に一時停止して画像認識をやり直すことを考えている。

**今後求められうる情報**（2026-11-01 fk-system 決定）: fk-system の盤前の旋回・並進で必要な精度が得られなかった場合、**画像認識によるフィードバック修正**の導入を検討する。そのときは本システムへの情報要求になる（`SS-A1`）。

### 1.2 推定の方法

**天板四隅の吊り金具を手がかりにする**（2026-10-31 ユーザー決定。fk-system 経由）。
方法と精度は検証レポート「[吊り金具による配電盤配置推定 検証レポート](https://claude.ai/artifact/A3Pz8dbXUn2srTn8NQFq2J)」（spec ではない。写さずにリンクする）。

| 項目 | 決まっていること |
| --- | --- |
| 検証の状態 | **合成データでだけ検証済み。実物の画像では未確認**（`SS-V1`） |
| 方法が前提にするもの | **カメラの位置・内部パラメータ**（検証レポートの前提）。位置はローカル座標系で返すので、LiDAR の地図上の自己位置は使わない（§1.1）。画像は本システムが動かすカメラから得る。**ヨーの向きは hve-system を改良して測れるようにする**（2026-11-01 ユーザー決定。方法は検討中）。ピッチの実際の角度は未定（`SS-A2`） |
| 先行試作 | `lifting-lug-pose`（[source/README.md](../source/README.md)）。**これを元に、適用させる形で入れる**（2026-11-01 ユーザー決定）。どこまで入れるか（コード・学習済みモデル・データ）は `SS-S1` |
| 動かす PC | **ノートパソコン（Ubuntu 22.04）。GPU は無い**（2026-11-01 ユーザー決定）。検証レポートの処理時間は GPU で測った値なので、CPU での処理時間を確かめる（`SS-V3`） |
| モデルを作る PC | **デスクトップ PC の GPU（RTX 4060 Ti 8GB）を使える**（2026-11-01 ユーザー決定） |
