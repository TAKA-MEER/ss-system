## 1. 対象

**配電盤上部を確認するロボットの画像認識を担うシステム**（2026-10-31 ユーザー決定。fk-system [Spec.md](../../../../fk-system/docs/plan/spec/Spec.md) `FD-9`）。
**fk-system（測定機能）から欲しい情報を受け取り、その情報を得るために hve-system のカメラを動かし、画像から推定した結果を返す**（2026-10-31 ユーザー決定。`SSD-3`）。
**配電盤の位置を返すだけの機能として、ほかのシステムから要求される**（2026-11-01 ユーザー決定。`SSD-6`）。
**仕様は fk-system の設計が決める。ただし fk-system 専用にせず、汎用的になるよう意識する。将来作るかもしれない、th-system の前日準備（th-system [Spec-onsite.md](../../../../th-system/docs/plan/spec/Spec-onsite.md) §2）を自動化するシステムにも対応できるようにする**（2026-10-31 ユーザー決定。`SSD-4`）。

| 担当 | 範囲 | 出典 |
| --- | --- | --- |
| **本システム** | **画像認識。**fk-system から欲しい情報を受け取り、**その情報を得るために hve-system のカメラを動かして**推定し、結果を返す | 2026-10-31 ユーザー決定 |
| fk-system | 測定機能。本システムに欲しい情報を渡し、返った結果を使って判断する（人の代わりに操作の判断の一部を行う）。**本システムの仕様を決める** | fk-system [Spec.md](../../../../fk-system/docs/plan/spec/Spec.md) §1・`FD-8`・`FD-9`・`FD-10` |
| th-system | 配電盤上部を確認するロボットのうち、移動に関わるすべて | th-system [Spec.md](../../../../th-system/docs/plan/spec/Spec.md) §1 |
| hve-system | th-system の走行部に載る昇降機と上部カメラ。**カメラと昇降機を本システムが動かす**（昇降機は fk-system も動かす。`SSD-5`） | hve-system [Spec.md](../../../../hve-system/docs/plan/spec/Spec.md) §1 ／ 動かすのは 2026-10-31 ユーザー決定 |

走行の指示は fk-system が出し、走行とカメラ・昇降を組み合わせる判断も fk-system が持つ（fk-system [Spec.md](../../../../fk-system/docs/plan/spec/Spec.md) §1・`FD-2`）。

**昇降機の操作**（2026-10-31 ユーザー決定。`SSD-5`）: **本システムはカメラの位置合わせに昇降機を動かす。fk-system も測定機構を動かすのに昇降機を使う。**
**本システムが昇降機を動かしている間に fk-system が動かさないよう気をつけるのは、指示を出す fk-system。本システムに気にする義務はない。**

### 1.1 求められている情報

**受け取るもの・返すもの**（2026-11-01 ユーザー決定）:

| 項目 | 決まっていること |
| --- | --- |
| 受け取るもの | **盤の位置を探す方向の範囲**（要求する側が指示する） |
| 返すもの | **その範囲にある配電盤の位置** |
| 座標 | **ローカル座標系。LiDAR の地図は考慮しない**。**依頼を受けた時点の機体を基準にする**（機体の中心・床・前向き。2026-11-04 fk-system 決定） |
| 返す中身 | **盤ごとに、天面の矩形（中心・高さ・向き・幅・奥行き）と確からしさ。**見つからないときは**空の一覧と理由**（2026-11-04 fk-system 決定） |
| 依頼の終わり | **「結果」と「後片付けの完了（カメラと昇降機から手を離した）」を分けて返す**（2026-11-04 fk-system 決定）。依頼した側は、後片付けの完了を受けるまで機体と昇降機を動かさない（座標の基準はこれを前提にする） |
| 取り消し | **依頼した側は取り消せる。**取り消されたら操作をやめ、後片付けをして完了を返す（2026-11-04 fk-system 決定） |
| 測る点 | 返さない。fk-system が盤の位置から決める |
| 見た方向の範囲 | **実際に撮って推定にかけた方位角の範囲（複数可）も返す**（2026-11-05 ユーザー決定。fk-system の相談に答えた）。取り消し・時間切れ・中断で依頼された範囲の一部しか見ていないときも、依頼した側が「見ていない方向」を知れるようにする |

天面の矩形の「向き」は、吊り金具からは表と裏を区別しない。どちらを正面とみなすかは依頼した側が決める（fk-system は、認識したときに機体に向いていた辺を正面とみなす。fk-system [Spec-auto.md](../../../../fk-system/docs/plan/spec/Spec-auto.md) §2）。

**受け渡しの細部**（2026-11-05 ユーザー決定。**fk-system へは未送付**。[Spec-open.md](Spec-open.md) §1.2）:

| 項目 | 決まっていること |
| --- | --- |
| 方向の範囲 | **機体を基準にした方位角の範囲**（開始と終了。機体の前が 0°）。必要なら最大の距離も付ける |
| 制限時間 | **依頼した側が指定する。**過ぎたら「時間切れ」を理由にして、後片付けをして返す |
| 高さ | **既定値（2350 mm。パラメータで変えられる）を返し、測った値ではないことを示す**（カメラ 1 台では盤の高さは測れない） |
| 確からしさ | **位置の標準偏差 [m]・向きの標準偏差 [°]・使った吊り金具の数。**しきい値は依頼した側が決める |
| 向き・幅・奥行き | **機体側に最も向いている辺を基準の辺とし、その長さを幅とする**（fk-system が正面とみなす辺と揃う。盤 1 面だけのときに幅と奥行きが入れ替わる問題が起きない） |
| 正面が分かるとき | 背中合わせの盤（吊り金具 2 個）は正面まで分かるので、**「正面が分かっている」印を付けて返す**（追加の情報。使わなくてよい） |
| 見つからない理由 | 範囲に吊り金具が見えない ／ 吊り金具は見えたが盤に組めない ／ 画像が取れない ／ 昇降機が動かない・拒否された ／ 必要な高さまで上がれない（2026-11-05 ユーザー決定）／ 取り消された ／ 時間切れ ／ 人の操作で中断 |
| 吊り金具が外された盤 | **対象外**（見つからない扱い）。この方法の制約 |
| 人が操作に割り込んだとき | hve-system は最後の操作が勝つ。**本システムはすぐ止まり、昇降機を元の高さに戻さずに手を離し、「人の操作で中断」を理由に完了を返す**（2026-11-05 ユーザー決定）。デジタルズームの倍率は変えない（倍率に関係なく全体が写る静止画を取る）。自動で操作中であることの画面表示は hve-system の見解どおり |
| 画像によるフィードバック修正 | fk-system の旋回・並進の精度が分かるまで決めない（`SS-A1`） |

fk-system の測定の流れ（fk-system [Spec.md](../../../../fk-system/docs/plan/spec/Spec.md) §1.1）での使われ方:

| 場面 | 得るために本システムが行うカメラの操作 |
| --- | --- |
| **自律測定の起動直後の配置図**（fk-system §1.1.2）。**起動のたびに作り直す**（前日の地図に関係なく。fk-system `FD-13`） | カメラを上げて周囲を撮る |
| **お立会試験中の測定・自律測定の盤前**（fk-system §1.1.1） | **カメラに天面が映るまで走査し、見つけたら推定に最適な画角に合わせる**（最適な画角は `SS-V2`） |

カメラを上げる・走査するのに、**昇降機も本システムが動かす**（`SSD-5`）。**終わったら後片付けとして、昇降機を元の高さに戻す**（2026-11-01 ユーザー決定）。fk-system はこれを当てにせず、走行の前に自分で確かめて下げる（fk-system `FD-14`）。
**画像は、必要なときだけフルサイズの静止画を要求する**（2026-11-01 ユーザー決定。`SS-A6` を決めた）。**フルサイズは 1280×720（720p）**。倍率に関係なく全体が写る 1 枚（hve-system の実機のカメラで 1920×1080 が取れなかったため。hve-system [Spec-ui.md](../../../../hve-system/docs/plan/spec/Spec-ui.md) §1.5・`H-V10`）。**推定の精度とカメラの内部パラメータは、この解像度を前提にする**（2026-11-01 hve-system の実装管理担当からの伝言）。
**移動中はカメラが揺れるので、画像認識はできない前提**（fk-system 決定）。配置図の精度を上げるために、fk-system は定期的に一時停止して画像認識をやり直すことを考えている。

**今後求められうる情報**（2026-11-01 fk-system 決定）: fk-system の盤前の旋回・並進で必要な精度が得られなかった場合、**画像認識によるフィードバック修正**の導入を検討する。そのときは本システムへの情報要求になる（`SS-A1`）。

### 1.2 推定の方法

**天板四隅の吊り金具を手がかりにする**（2026-10-31 ユーザー決定。fk-system 経由）。
方法と精度は検証レポート「[吊り金具による配電盤配置推定 検証レポート](https://claude.ai/artifact/A3Pz8dbXUn2srTn8NQFq2J)」（spec ではない。写さずにリンクする）。

| 項目 | 決まっていること |
| --- | --- |
| 検証の状態 | **合成データでだけ検証済み。実物の画像では未確認**（`SS-V1`） |
| 吊り金具の数 | **四隅すべてに付いているとは限らない。前側の 2 個だけのことが多い**（2026-11-05 ユーザー確認）。先行試作はこの前提で直している途中 |
| 方法が前提にするもの | **カメラの位置・内部パラメータ**（検証レポートの前提）。位置はローカル座標系で返すので、LiDAR の地図上の自己位置は使わない（§1.1）。画像は本システムが動かすカメラから得る。**ヨーの向きは hve-system を改良して測れるようにする**（2026-11-01 ユーザー決定。方法は検討中）。高さ・ピッチ・内部パラメータの出どころは下の「カメラの位置・内部パラメータの出どころ」 |
| 先行試作 | `lifting-lug-pose`（[source/README.md](../source/README.md)）。**これを元に、適用させる形で入れる**（2026-11-01 ユーザー決定）。**ひとまず、先行試作をなるべく使い、本システムの仕様に合わせる**（2026-11-05 ユーザー決定）。**推定の部分（吊り金具から盤への組み立てと射影）を写してローカル座標に直し、画像から盤までの推定の入口は新しく作る。学習済みモデルは git に入れず、SHA-256 で指す。合成データの生成・学習・評価は先行試作の側に残す**（2026-11-05 ユーザー決定）。**学習済みモデルはこのリポジトリの中に置く（git には入れない）**（2026-11-05 ユーザー決定） |
| 動かす PC | **ノートパソコン（Ubuntu 22.04）。GPU は無い**（2026-11-01 ユーザー決定）。検証レポートの処理時間は GPU で測った値なので、CPU での処理時間を確かめる（`SS-V3`） |
| モデルを作る PC | **デスクトップ PC の GPU（RTX 4060 Ti 8GB）を使える**（2026-11-01 ユーザー決定） |
| 動かす形 | **実機のノートパソコンでも、Windows でも、本システムは Docker（Ubuntu 22.04）で動かす**（2026-11-05 ユーザー決定） |
| 依頼の通り道 | **ROS 2（Humble）で通す。実機では fk-system と同じ PC で動かし、設定は fk-system に揃える（ホストのネットワーク・同じドメイン ID・UDP だけ）**（2026-11-05 ユーザー決定。fk-system の相談に答えた）。名前と形は提供する側の本システムが詳細設計に書き、fk-system が確かめる。ROS 2 以外の口は要るときに外側に足す |
| カメラの位置・内部パラメータの出どころ | **高さは hve-system の昇降部が配信する値。ピッチはカメラを動かすサーボのピッチ（目標角）を信頼する。内部パラメータは 1280×720 でチェッカーボードを使って 1 回校正し、パラメータとして持つ**（2026-11-05 ユーザー決定）。ヨーは hve-system の改良待ち（`SS-A2`） |
| 撮り方 | **カメラを天板より 0.6〜0.9 m 上（床から約 2.95〜3.25 m）に上げ、見下ろし 10° 以上で撮る。盤まで 5 m 以内を前提にする。ピッチを固定し、依頼された方向の範囲を、画角が少し重なる刻みでヨーを振って撮る**（2026-11-05 ユーザー決定。先行試作の結果から。[source/lifting-lug-pose.md](../source/lifting-lug-pose.md) §6）。**天井の距離の制限などで撮る高さまで上がれないときは、撮らずに「必要な高さまで上がれない」を理由にして、後片付けをして返す**（低い位置からの精度は確かめていないため。2026-11-05 ユーザー決定。上がれない場所はありうる: hve の答え。`SS-V2`） |
| 使う道具 | **Docker（Ubuntu 22.04）の中で Python と ultralytics。試験は pytest**（2026-11-05 ユーザー決定）。**ultralytics は AGPL-3.0 に従って使う**（2026-11-05 ユーザー決定）。CPU で遅すぎれば CPU 向けの形式に変換する（詳細設計） |
| 開発・検証の環境 | **開発に CG と GPU を使うため、Windows でも WSL と Docker を用いて動かし、検証できるようにする。合成データの描画と学習は WSL の外（Windows）で行い、WSL の Docker で動作を確かめる**（2026-11-05 ユーザー決定） |

## 3. 目標

**th-system の目標と設計思想の大まかな考え方は引き継ぐが、目標というほど厳密にはしない**（2026-11-01 ユーザー決定。fk-system と同じ）。

## 5. 全体構成

**§1・§1.1・§1.2 で決まったものを 1 か所にまとめた**（新しく決めたものは無い。中身の正はそれぞれの節）。
ノード名・ファイル構成は書かない（詳細設計 [DetailedDesign.md](../detailed/DetailedDesign.md) §2）。

```
 [ 依頼する側（fk-system ほか） ]
          │ ROS 2（同じノートパソコンの別コンテナ）
          │ 方向の範囲 → 盤の位置・後片付けの完了
 [ 本システム（ノートパソコン・Docker・CPU） ]
          │ hve-system の口（上部モジュールの 1 つとして繋ぐ）
     ┌────┴────────────────┐
 [ 昇降部 ]            [ カメラモジュール ]
  高さ・目標の高さへ     静止画 1280×720・ヨー・ピッチ
```
